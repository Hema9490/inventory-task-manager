# Inventory & Task Manager (with AI-Assisted Restock Forecasting)

A Flask REST API that manages inventory items, tasks, and sales/restock
orders, with a lightweight ML layer that forecasts when an item will run
out of stock. Built to be end-to-end explainable: no hidden ORM magic,
no black-box model imports — every SQL query and every algorithm is
hand-written and testable in isolation.

## 1. Requirements (SRS summary)

**Problem:** A small operations team needs to track inventory levels,
generate and prioritize restocking/operational tasks, and get an early
warning before an item runs out.

**Functional requirements:**
- CRUD for inventory items (SKU, quantity, reorder threshold, price).
- CRUD-style task management with priority levels and a status lifecycle
  (open → in-progress → closed).
- Order recording for sales (deducts stock) and restocks (adds stock).
- Automatic task creation when a sale pushes an item at/below its
  reorder threshold.
- Reporting: low-stock items, sales trend by category/date, task load
  by status.
- A restock forecast: given an item's recent sales history, predict
  days until stockout.

**Non-functional requirements:**
- Every business rule must be unit-testable without a live database.
- The SQL layer must be inspectable (no ORM-generated queries) for the
  reporting endpoints.
- The priority logic must use an explicit, documented data structure
  (not just "sort a list every time").

## 2. Design

### 2.1 Architecture

```
app/
  __init__.py        Flask app factory, blueprint registration
  db.py               Raw sqlite3 connection handling + schema + report SQL
  models.py           OOP domain classes: Item, WorkItem, Task, RestockTask, Order
  priority_queue.py   Heap-backed PriorityQueue (DSA)
  search_sort.py      Binary search + merge sort over Item lists (DSA)
  ml/
    restock_predictor.py   Linear-regression-based stockout forecast
  routes/
    items.py           /api/items
    tasks.py            /api/tasks
    orders.py           /api/orders
    reports.py          /api/reports
tests/                 61 unit + integration tests (pytest)
```

### 2.2 Design decisions

- **No ORM.** Raw `sqlite3` + hand-written SQL was chosen deliberately
  so joins/aggregates (see `db.py`) are visible and reviewable, rather
  than generated by an ORM layer.
- **OOP with inheritance.** `Task` and `RestockTask` both extend a
  `WorkItem` base class so the priority queue can operate on either
  polymorphically; `RestockTask` derives its priority from the item's
  shortfall rather than being manually set.
- **Explicit DSA, not just built-ins.** `PriorityQueue` is a documented
  binary-heap wrapper (not a bare `heapq` call inline), and
  `search_sort.py` implements binary search and merge sort by hand so
  their complexity (O(log n), O(n log n)) is visible in the code, not
  hidden behind `sorted()`.
- **Transparent ML.** The restock predictor fits a fresh linear
  regression per request over that item's own order history — no saved
  model files, no external service call. It's designed to be walked
  through line-by-line in an interview.

### 2.3 Data model

- `items(id, sku, name, category, quantity, reorder_threshold, unit_price, created_at)`
- `orders(id, item_id, quantity, order_type, created_at)` — `order_type` is `sale` or `restock`
- `tasks(id, title, description, priority, status, related_item_id, created_at, completed_at)`

## 3. API Reference

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/items` | Create an item |
| GET | `/api/items` | List items (`?sort=quantity` for merge-sort order) |
| GET | `/api/items/lookup/<sku>` | Binary-search lookup by SKU |
| GET | `/api/items/<id>` | Get one item |
| PUT | `/api/items/<id>` | Update an item |
| DELETE | `/api/items/<id>` | Delete an item |
| POST | `/api/tasks` | Create a task |
| GET | `/api/tasks` | List tasks (`?status=open`) |
| GET | `/api/tasks/next` | Pop the highest-priority open task |
| PUT | `/api/tasks/<id>/start` | Mark task in-progress |
| PUT | `/api/tasks/<id>/complete` | Mark task closed |
| POST | `/api/orders` | Record a sale or restock; auto-creates a restock task if stock drops low |
| GET | `/api/orders` | List orders |
| GET | `/api/reports/low-stock` | Items at/below reorder threshold |
| GET | `/api/reports/sales-trend` | Revenue/units by category and date |
| GET | `/api/reports/task-load` | Task counts by status |
| GET | `/api/reports/restock-prediction/<item_id>` | ML-based days-until-stockout forecast |

## 4. Testing

61 tests across unit (domain models, priority queue, search/sort, ML
predictor) and integration (full API round-trips via Flask's test
client) layers.

```bash
pip install -r requirements.txt
python -m pytest tests/ -v
```

## 5. Running locally

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

Server runs at `http://localhost:5000`. Try:

```bash
curl -X POST http://localhost:5000/api/items \
  -H "Content-Type: application/json" \
  -d '{"sku":"A100","name":"Bolt","category":"hardware","quantity":10,"reorder_threshold":5,"unit_price":2.5}'
```

## 6. Deployment (Render)

1. Push this repo to GitHub.
2. On Render: **New → Web Service**, connect the repo.
3. Build command: `pip install -r requirements.txt`
4. Start command: `gunicorn "app:create_app()"` (already set in `Procfile`)
5. No environment variables are required for the default SQLite setup.

Note: Render's free-tier filesystem is ephemeral, so the SQLite database
resets on redeploy/restart. That's fine for a demo; for persistence,
swap `DATABASE` in `app/__init__.py` for a managed Postgres URL.

## 7. Tech stack

Python, Flask, SQLite (raw SQL, no ORM), scikit-learn, NumPy, pytest,
